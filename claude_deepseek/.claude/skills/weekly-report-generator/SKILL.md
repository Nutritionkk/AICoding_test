# Weekly Report Generator

生成本周工作周报：扫描 Git 提交记录和 TODO 变更，输出结构化 Markdown 文件。

## 何时使用

- 用户要求生成周报、本周总结、本周工作汇报
- 用户询问"本周做了哪些事""这周的提交有哪些"
- 任何需要汇总一段时间内 Git 活动并输出文档的场景（用户可指定非本周的时间范围，流程相同）

## 工作流程

### 第 1 步：确定时间范围和扫描范围

**时间范围**：默认覆盖**最近一个自然周**（周一起始），语义是"汇报最近完成/进行中的这一周"：

- git 的日期近似解析中 `"last Monday"` = 今天之前最近的周一（不含今天）：
  - 周二~周日：`"last Monday 00:00"` = 本周一 00:00 → 报告本周一至今
  - **周一当天：`"last Monday 00:00"` = 上周一 00:00 → 报告刚结束的上一整周**（周一写周报应汇报上周，新的一周尚无内容）
- 裸 `"Monday"` = 今天 00:00（若今天是周一），与 `"last Monday"` 不同，注意区分

统一使用 `--since="last Monday 00:00" --until=now` 即可覆盖上述两种情况，无需分支。用户指定起止日期时以用户为准，转换为 `YYYY-MM-DD HH:MM` 格式传入 `--since` / `--until`。

**扫描范围**：默认整个当前 git 仓库。注意：git 仓库根目录可能与当前工作目录不一致（先用 `git rev-parse --show-toplevel` 确认）。如果用户提到具体项目或目录（如"只看 claude_deepseek"），在 git 命令末尾追加 `-- <path>` 限定范围。

**环境约束**：本项目在 Windows 上运行，中文提交信息需要编码参数，所有 git log/show 命令统一加：

```
-c core.quotepath=false -c i18n.logOutputEncoding=UTF-8
```

否则中文会显示为 `\346\217\220\344\272\244` 这类转义或乱码。

### 第 2 步：扫描本周提交记录

运行以下命令获取提交列表（hash、作者、时间、主题）：

```bash
git -c core.quotepath=false -c i18n.logOutputEncoding=UTF-8 log \
  --since="last Monday 00:00" --until=now \
  --pretty=format:"%h|%an|%ad|%s" --date=format:"%Y-%m-%d %H:%M"
```

统计信息（提交数、文件变更数）：

```bash
# 提交总数
git log --since="last Monday 00:00" --oneline | wc -l
# 涉及文件与增删行数（逐提交列出）
git log --since="last Monday 00:00" --stat
```

**分类**：先按提交信息前缀将提交归类：

- `feat` → 功能开发
- `fix` / `bugfix` → 修复
- `refactor` / `perf` → 重构与优化
- `docs` → 文档
- `test` → 测试
- `chore` / `build` / `ci` → 工程与维护

无前缀的提交不要机械地扔进"其他"：根据语义归类（如 "Add ... app/page/module" → 功能开发，"Remove ..." → 重构或修复）。确实无法判断的才归入"其他"。

按分类重组为周报内容，每项格式：`- <短hash> <主题>（<作者>）`。

### 第 3 步：扫描 TODO/FIXME 变更

目标：找出本周内代码注释中 TODO/FIXME 的新增、删除和完成情况。

1. 找出触及 TODO/FIXME 行的本周提交（`-S` 按文本内容变化过滤，只列出改变了该字符串出现次数的提交）：

```bash
git -c core.quotepath=false log --since="last Monday 00:00" \
  -S"TODO" --oneline
# 再对 FIXME 执行一次
git -c core.quotepath=false log --since="last Monday 00:00" \
  -S"FIXME" --oneline
```

2. 对每个命中的提交，用 `git show <hash>` 查看具体变更，判断每条 TODO 属于：
   - **新增 TODO**：diff 中 `+` 行出现 TODO 注释
   - **已完成/移除的 TODO**：diff 中 `-` 行删除了 TODO 注释（通常意味着该事项已处理）
   - **修改**：TODO 内容变化（如更新描述、移动位置）

   记录 `文件:行号` 和 TODO 内容。

3. 用 `git grep -n -E "TODO|FIXME" HEAD` 扫描当前代码中仍存在的 TODO，作为"遗留 TODO"列出。若扫描范围限定子目录，追加 `-- <path>`。

### 第 4 步：生成周报文件

输出路径：`reports/weekly-<生成日期>.md`（生成日期格式 YYYY-MM-DD，如 `weekly-2026-11-23.md`）。`reports/` 目录不存在则创建。用户指定了其他路径时以用户为准。

**模板**（结构固定，内容按实际数据填写）：

```markdown
# 周报：<周期起始日期> ~ <周期结束日期>

> 生成时间：<当前时间> ｜ 仓库：<repo 根目录名> ｜ 分支：<当前分支> ｜ 扫描范围：<全部或指定路径>

## 本周概览

- 提交 <N> 个，涉及 <M> 个文件，作者 <K> 人：<作者列表>
- 主要方向：<一句话总结本周工作主题>

## 工作内容

### 功能开发
- <短hash> <主题>（<作者>）

### 修复
- ...

### 重构与优化
- ...

### 文档 / 测试 / 工程与维护 / 其他
- ...（没有内容的分类省略该小节）

## TODO 变更

### 新增 TODO
- `<文件:行号>` <内容>

### 已完成 / 移除的 TODO
- `<文件>` <内容>

### 遗留 TODO（当前代码中仍存在）
- `<文件:行号>` <内容>

## 下周计划

基于遗留 TODO 和本周进行中的工作推断，列出建议的下周事项。这部分是推断，标注"（推断）"。

## 风险与阻塞

本周未完成的事项、遗留 TODO 中标注为紧急/阻塞的内容。没有则写"无明确风险"。
```

**周期起止日期**：用 `git log --since="last Monday 00:00"` 拿到的最早提交日期反推周期起点；若今天不是周一，周期 = 本周一 ~ 今天；若今天是周一（`date +%u` 输出 1），周期 = 上周一 ~ 昨天。

### 第 5 步：验证并汇报

- 确认周报文件已写入正确路径
- 向用户汇报：周报路径、本周提交数、TODO 变更数（新增 X 条、完成 Y 条、遗留 Z 条）
- 用 Read 打开生成的周报给用户展示摘要（可选）

## 边界情况

- **本周无提交**：生成周报但概览写"本周无提交"，各分类为空；若 TODO 无变更，明确告知用户并询问是否需要生成本周无内容的周报文件
- **仓库根 ≠ 工作目录**：第 1 步已确认，若仓库包含多个项目，默认全部扫描并在周报中按目录分组，或询问用户关注哪个项目
- **TODO 出现次数不变但内容变化**：`-S` 可能漏掉（例如删一条又加一条），用 `--since` 全量 diff 兜底检查：`git log --since="last Monday 00:00" -p | grep -E "^[+-].*(TODO|FIXME)"`
- **跨周提交**：周日晚间生成时，`--until=now` 已保证只含本周；用户指定自定义范围时同理
